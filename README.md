### П.4: Демонстрация работы с бэкендом на ПК (подробно)

**Цель:** на компьютере показать, что приложение получает данные с вашего бэкенда (не mock).

**Почему не открывать буквально GitHub Pages:**  
Сайт `https://seregapi15.github.io/react_RIP/` отдаётся с серверов GitHub. Запросы из браузера идут на тот же домен (`/api/...` → `seregapi15.github.io/api/...`). Там нет вашего бэкенда, поэтому с этого URL данные с вашего ПК не подгрузятся (будет mock или ошибка). Чтобы показать «работу с бэкендом», приложение нужно открыть так, чтобы запросы шли на ваш ПК — через **локальный фронт**.

**Что сделать по шагам:**

1. **Запустить бэкенд на ПК**  
   В папке бэкенда:
   ```bash
   cd backend_RIP
   docker-compose up --build
   ```
   Дождаться сообщения, что API слушает порт **8081**. Проверка: в браузере открыть http://localhost:8081/swagger/ — должна открыться Swagger.

2. **Запустить фронтенд на ПК**  
   В папке фронта:
   ```bash
   cd react_RIP
   npm run dev
   ```
   Должно быть: `Local: http://localhost:3000`. В `vite.config.js` настроен proxy: запросы на `/api` уходят на `http://localhost:8081`.

3. **Открыть приложение в браузере**  
   Перейти по адресу: **http://localhost:3000**  
   Это то же приложение, что задеплоено на GitHub Pages, но запущено локально и через прокси ходит в ваш бэкенд.

4. **Показать, что данные с бэкенда**  
   - Зайти в **Каталог инструментов**. Должны отображаться инструменты из вашей БД (и/или предупреждение «Бэкенд недоступен» должно **исчезнуть**).  
   - Открыть **DevTools** (F12) → вкладка **Network** (Сеть). Обновить страницу или перейти в каталог. Найти запрос к **`/api/services`** (или с query-параметрами). Открыть его: во вкладке **Response** (Ответ) или **Preview** — JSON со списком инструментов с вашего API. Статус запроса — **200**.

5. **Что сказать на защите**  
   «На компьютере запущен бэкенд на 8081 и фронт на 3000. Фронт обращается к API по относительному пути `/api`; Vite проксирует эти запросы на localhost:8081. Во вкладке Network видно запрос к `/api/services` и ответ 200 с данными с сервера — значит приложение работает с бэкендом.»

**Кратко:** бэкенд (8081) + фронт локально (3000) → в браузере открыть localhost:3000 → каталог без mock → в Network виден успешный запрос к API.

### П.5: Tauri build и работа с бэкендом (подробно, без ZeroTier)

**Цель:** собрать нативное приложение Tauri (не режим dev), подключить его к бэкенду по IP локальной сети и показать загрузку данных.

**Почему нужен IP, а не localhost:**  
В собранном Tauri нет Vite и прокси. Запросы к `/api` ушли бы на тот же origin (файловый или пустой), бэкенд не доступен. Поэтому в коде явно задаётся полный адрес бэкенда: `http://<IP>:8081`. Используется IP вашего ПК в обычной сети (Wi‑Fi или Ethernet), без ZeroTier.

---

**Шаг 1. Узнать IP ПК в локальной сети**

- **Windows:** откройте cmd или PowerShell, выполните:
  ```text
  ipconfig
  ```
  Найдите блок **«Адаптер беспроводной локальной сети»** (Wi‑Fi) или **«Ethernet»**. Строка **IPv4-адрес** — нужный IP (например, `192.168.1.105`).
- Запомните или скопируйте этот адрес (без порта).

**Шаг 2. Прописать IP в коде**

Откройте файл **`react_RIP/src/config/target.ts`**.

Измените константу **`BACKEND_IP`** на IP из шага 1:

```ts
export const BACKEND_IP = '192.168.1.105';  // ваш IP из ipconfig
```

Сохраните файл. От этого значения собирается `API_BASE_IP` (например, `http://192.168.1.105:8081`), к нему обращается Tauri.

**Шаг 3. Убедиться, что бэкенд запущен**

В папке бэкенда:

```bash
cd backend_RIP
docker-compose up --build
```

API должен слушать порт **8081**. Проверка в браузере: http://localhost:8081/swagger/ — открывается Swagger.

**Шаг 4. Собрать Tauri (build, не dev)**

В папке фронта:

```bash
cd react_RIP
npm run tauri build
```

Дождитесь окончания сборки (сначала собирается фронт, потом Rust). Ошибки компиляции Rust нужно исправить; при успехе в консоли будет путь к результату.

**Шаг 5. Найти и запустить .exe**

- Исполняемый файл лежит в каталоге:
  ```text
  react_RIP/src-tauri/target/release/
  ```
  Файл с именем вашего приложения (например, `exoplanets-rip.exe` или как в `tauri.conf.json` → `productName`).
- Либо установщик: **`react_RIP/src-tauri/target/release/bundle/`** — там .msi или .exe установщик; после установки запускаете приложение из меню Пуск.

Запустите именно этот собранный .exe, **не** `npm run tauri dev`.

**Шаг 6. Показать работу с бэкендом**

1. В открывшемся окне Tauri перейдите в **Каталог инструментов** (или главная → каталог).
2. Должен загрузиться список инструментов с вашего бэкенда (те же данные, что в браузере на localhost:3000 при запущенном бэкенде). Не должно быть сообщения «Бэкенд недоступен» и пустого списка из mock.
3. Откройте любую карточку → «Подробнее» — данные одной услуги тоже с API.
4. При необходимости откройте DevTools в окне Tauri: правый клик по окну → **«Проверить»** / **Inspect** — во вкладке Network будут видны запросы к `http://<ваш_IP>:8081/api/...` с ответами 200.

**Что сказать на защите:**  
«Собрал приложение командой `npm run tauri build`. В коде в `target.ts` указан IP бэкенда в локальной сети (не localhost). Запускаю собранный .exe — приложение получает данные с бэкенда по этому адресу; это не режим разработки.»

---

**Если Tauri показывает пустой список или «Бэкенд недоступен»:**

- Проверьте, что бэкенд запущен и Swagger открывается по http://localhost:8081/swagger/.
- Проверьте, что в `target.ts` указан тот же IP, что выдаёт `ipconfig` на этом ПК (если бэкенд на другом компьютере — укажите IP того компьютера).
- На Windows: фаервол может блокировать входящие на 8081 — разрешите приложению Go/backend или порт 8081 для частной сети.

### Доступ с телефона без ZeroTier (обычная Wi‑Fi сеть)

**Цель:** открыть приложение в браузере на телефоне по адресу в локальной сети, без ZeroTier.

**Условие:** телефон и ПК в одной Wi‑Fi сети.

1. **Узнать IP ПК в этой Wi‑Fi**  
   На ПК: `ipconfig` → блок **«Беспроводная локальная сеть»** (Wi‑Fi) → **IPv4-адрес** (например, `192.168.1.105`). Если ПК по кабелю — смотрите **Ethernet** (но тогда телефон должен быть в той же подсети).

2. **Бэкенд должен быть доступен с телефона**  
   Запуск: `docker-compose up --build` в `backend_RIP`. По умолчанию сервис слушает все интерфейсы (`0.0.0.0:8081`). Если нет — в конфиге бэкенда указать bind на `0.0.0.0`. На ПК в брандмауэре разрешить входящие на порт **8081** (частная сеть).

3. **Запустить фронт так, чтобы он был доступен по сети**  
   В `react_RIP`:
   ```bash
   npm run dev -- --host
   ```
   В консоли появится что-то вроде: `Network: http://192.168.1.105:3000`. Фронт будет отдавать страницы по этому адресу.

4. **Фронт должен ходить в API по IP ПК, а не по localhost**  
   В браузере на телефоне открывается `http://192.168.1.105:3000` — запросы с телефона идут с origin `http://192.168.1.105:3000`. В коде фронта API вызывается как `/api` (относительный путь) — браузер отправит запрос на `http://192.168.1.105:3000/api/...`. Но Vite-прокси работает только для запросов к самому dev-серверу: прокси на 3000 перенаправляет `/api` на localhost:8081. То есть запрос с телефона к `192.168.1.105:3000/api/services` придет на ПК на порт 3000, Vite перенаправит его на localhost:8081 — и бэкенд ответит. Так что **достаточно `npm run dev -- --host`** и на телефоне открыть **http://192.168.1.105:3000** (подставить свой IP). Данные должны подгружаться с бэкенда.

5. **Открыть на телефоне**  
   В браузере на телефоне ввести: **http://192.168.1.105:3000** (ваш IP из п. 1). Приложение откроется, каталог — с данными с бэкенда.

6. **HTTPS (по желанию)**  
   Если нужен HTTPS (например, для PWA с телефона): по методичке PWA настроить mkcert и в Vite включить `https` в `server`. Запускать с `--host`. На телефоне открывать **https://192.168.1.105:3000** (при первом заходе браузер может предупредить о сертификате — принять).

**Кратко:** ПК и телефон в одной Wi‑Fi → `ipconfig` → IP ПК → бэкенд запущен, порт 8081 открыт → `npm run dev -- --host` → на телефоне в браузере: **http://&lt;IP_PК&gt;:3000**.

### Доп. Lab 6: ZeroTier — виртуальная сеть, HTTPS, доступ с телефона

**Задача:** настроить виртуальную сеть ZeroTier, зафиксировать IP HTTPS-сервера в коде Tauri, открывать приложение в браузере на телефоне по адресу в виртуальной сети.

1. **Установка ZeroTier**  
   Скачать и установить [ZeroTier](https://www.zerotier.com/download/) на ПК и (опционально) на телефон. Зарегистрироваться в [ZeroTier Central](https://my.zerotier.com/).

2. **Создание сети**  
   В ZeroTier Central: **Create A Network**. Скопировать **Network ID** (например, `a0cbf4b62a8b8a8e`).

3. **Подключение ПК**  
   На ПК в ZeroTier: **Join Network** → вставить Network ID. В Central во вкладке **Members** появится устройство → нажать **Auth** (галочка), чтобы разрешить. Запомнить выданный ПК **IP** (например, `192.168.195.38`).

4. **Фиксация IP в коде**  
   В `src/config/target.ts` задать этот IP:
   ```ts
   export const ZEROTIER_SERVER_IP = '192.168.195.38';  // IP вашего ПК в ZeroTier
   ```
   Tauri и фронт будут использовать этот адрес для API и для URL с телефона.

5. **HTTPS на ПК (Vite)**  
   По методичке PWA: установить mkcert, сгенерировать сертификаты, в `vite.config.js` подключить `vite-plugin-mkcert` и в `server` указать `https: { key, cert }`. Запуск: `npm run dev` (или с `--host`, чтобы слушать все интерфейсы). Фронт будет доступен по `https://<ZEROTIER_SERVER_IP>:3000`.

6. **Подключение телефона**  
   На телефоне в ZeroTier присоединиться к той же сети (Join → Network ID) и авторизовать в Central. В браузере на телефоне открыть:
   **`https://192.168.195.38:3000`**  
   (подставить свой IP из п. 3). При первом заходе браузер может предупредить о сертификате — разрешить (для локального mkcert).

7. **Демонстрация**  
   Показать: IP зафиксирован в `target.ts` (ZEROTIER_SERVER_IP); Tauri подключается к бэкенду по этому IP; браузер на телефоне открыт по адресу в виртуальной сети (HTTPS).
